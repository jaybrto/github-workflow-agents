### Claude Authentication System (Completed — Key Outcome)
**Root cause discovered:** Claude Code 2.1.45 interactive TUI requires a `~/.claude/.credentials.json` with the `claudeAiOauth` format (NOT the legacy `oauthToken` format). This is different from headless `--print` mode. After one-time manual OAuth login on the pod, the correct format is:
```json
{
  "claudeAiOauth": {
    "accessToken": "sk-ant-oat01-...",
    "refreshToken": "sk-ant-ort01-...",
    "expiresAt": 1771498216719,
    "subscriptionType": "max",
    ...
  }
}
```

**What was built (`src/lib/credentials-manager.ts`):**
- `backupCredentials()` — tars `~/.claude/.credentials.json` + `~/.claude.json`, uploads to MinIO at:
  - `s3://gwa-recordings/claude-auth/pods/<POD_NAME>/credentials.tar.gz` (per-pod)
  - `s3://gwa-recordings/claude-auth/credentials.tar.gz` (legacy fallback)
- `restoreCredentialsIfMissing()` — on new pod startup, tries: own pod backup → other pods' backups → legacy. Any pod's refresh token works.
- `syncConfigFromCredentials()` — recreates ephemeral `~/.config/claude/config.json` from the PVC-backed credentials file on every pod start.
- `src/credentials-backup.ts` + `build:credentials-backup` binary.
- `k8s/gwa-credentials-backup-cronjob.yaml` — runs every 6 hours, mounts `claude-session-gwa-runner-0` PVC.
- `k8s/gwa-runner-configmap.yaml` updated — entrypoint syncs `~/.config/claude/config.json` from credentials on every pod start.

**Manual auth was done:** The pod (`gwa-runner-0`) is currently authenticated. Credentials backed up to:
- `s3://gwa-recordings/claude-auth/pods/gwa-runner-0/credentials.tar.gz`
- `s3://gwa-recordings/claude-auth/credentials.tar.gz`
